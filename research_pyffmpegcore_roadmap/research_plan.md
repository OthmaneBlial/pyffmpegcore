# PyFFmpegCore adoption research plan

## Main question

What is PyFFmpegCore genuinely missing to become a compelling, trustworthy, and highly discoverable Python/FFmpeg project on GitHub?

## Research tracks

### 1. Repository product and technical audit

Map the current API, CLI, packaging, documentation, examples, tests, automation, and release evidence. Identify the strongest existing capabilities and the concrete gaps that block a fast first success or dependable production use.

### 2. Python/FFmpeg competitive landscape

Compare the positioning and adoption signals of maintained FFmpeg-related Python projects and official FFmpeg capabilities. Look for underserved use cases rather than proposing a generic clone.

### 3. GitHub adoption, trust, and distribution

Assess repository presentation, installability, compatibility proof, security/release practices, contribution paths, and content/distribution loops that could turn genuine usefulness into sustained GitHub adoption.

## Synthesis

Combine repository evidence with current primary-source evidence. Prioritize work by dependency and user impact. Every roadmap phase should state its outcome, deliverables, measurable acceptance criteria, and explicit non-goals. The result must avoid guaranteeing virality or star counts.
