# PyAV — vérification du 19 septembre 2026

Sources primaires : [dépôt officiel](https://github.com/PyAV-Org/PyAV) et [documentation officielle stable 18.1.0](https://pyav.basswood.io/docs/stable/). Le dépôt renvoie lui-même vers `pyav.basswood.io`. L'ancien domaine `pyav.org/docs/stable/` sert encore une documentation 9.0.2 ; les constats ci-dessous portent sur 18.1.0.

## Faits vérifiés

- PyAV se présente comme des *bindings* Python des bibliothèques FFmpeg, destinés à l'accès précis aux conteneurs, flux, paquets, codecs et images audio/vidéo. Sa page d'accueil documente aussi les graphes de filtres, le reformatage vidéo et le rééchantillonnage audio. [Documentation officielle](https://pyav.basswood.io/docs/stable/).
- `InputContainer.decode()` livre des images décodées ; `InputContainer.demux()` livre des paquets que l'on peut ensuite décoder. `OutputContainer` fournit notamment `add_stream()`, `add_mux_stream()` pour données déjà encodées et `mux()`. [API conteneurs](https://pyav.basswood.io/docs/stable/api/container.html). Un paquet est une unité de données encodées, qui ne correspond pas nécessairement à une image entière ; il porte notamment horodatages et informations de flux. [API paquets](https://pyav.basswood.io/docs/stable/api/packet.html).
- Les flux vidéo exposent `decode(packet)` → images et `encode(frame)` → paquets ; le conteneur de sortie les multiplexe. [API vidéo](https://pyav.basswood.io/docs/stable/api/video.html). Les exemples officiels montrent un remuxage sans transcodage et le traitement de paquets. [Cookbook Basics](https://pyav.basswood.io/docs/stable/cookbook/basics.html).
- `VideoFrame` expose dimensions, format et plans, la conversion vers une image Pillow ou un tableau NumPy, la création depuis ceux-ci et le reformatage. Le cookbook lit les pixels de chaque image pour produire un « video barcode », puis crée un MP4 à partir de tableaux NumPy en encodant et multiplexant chaque image. [API vidéo](https://pyav.basswood.io/docs/stable/api/video.html), [cookbook NumPy](https://pyav.basswood.io/docs/stable/cookbook/numpy.html).
- La version stable documente également `HWAccel` pour décodage et encodage matériel selon les périphériques et codecs disponibles dans la bibliothèque FFmpeg chargée. Éviter d'affirmer que PyAV n'a aucune prise en charge matérielle. [API codecs](https://pyav.basswood.io/docs/stable/api/codec.html).
- Le README du dépôt annonce des wheels Linux, macOS et Windows avec FFmpeg embarqué et Python 3.12 ou plus ; cela décrit l'installation PyAV, pas la disponibilité de tous les codecs et périphériques sur toute machine. [README officiel](https://github.com/PyAV-Org/PyAV).

## Déductions pour le positionnement (à présenter comme telles)

- PyAV convient quand du code Python doit **lire, analyser, modifier ou fabriquer des images ou des paquets individuels** : vision par ordinateur/NumPy, traitement image par image, logique de décodage ou de multiplexage fine. Cette conclusion découle des API et exemples ci-dessus ; ce n'est pas un benchmark.
- Pour une conversion ou un remuxage exprimable par une commande `ffmpeg`, la documentation PyAV dit elle-même que son niveau de contrôle peut ajouter de la complexité. Une comparaison honnête devrait distinguer une couche de pilotage du CLI FFmpeg, avec recettes et validation de sorties, d'une bibliothèque donnant accès aux images/paquets. Elle ne devrait pas dire que PyAV ne sait pas transcoder, remuxer ou filtrer. [Documentation officielle](https://pyav.basswood.io/docs/stable/), [API conteneurs](https://pyav.basswood.io/docs/stable/api/container.html).
