# FFmpeg CLI and ffmpeg-python — 19 September 2026

Scope: documented capabilities relevant to inspecting an input, planning a conversion, previewing the command, running it, and retaining evidence. Sources are the projects' own documentation and repository. These are documentation findings, not a benchmark or a hands-on validation of either competitor.

| Step | FFmpeg CLI, documented | ffmpeg-python, documented |
| --- | --- | --- |
| Inspect input | `ffprobe` reports container and stream properties and supports machine-readable JSON (`-of json`, `-show_format`, `-show_streams`). [ffprobe manual](https://ffmpeg.org/ffprobe.html) | `ffmpeg.probe(filename)` invokes ffprobe and returns parsed JSON. [API reference](https://kkroening.github.io/ffmpeg-python/) |
| Construct conversion | `ffmpeg -i input.avi output.mp4` is an official example; the manual covers stream mapping, streamcopy, transcoding, and complex filters. Argument order matters. [ffmpeg manual](https://ffmpeg.org/ffmpeg.html) | `ffmpeg.input(...).output(...)` builds an FFmpeg node graph; README examples include filters and multiple inputs. Arbitrary FFmpeg options can be passed as keyword arguments. [README](https://github.com/kkroening/ffmpeg-python), [API reference](https://kkroening.github.io/ffmpeg-python/) |
| Preview exact invocation | The CLI invocation is already explicit in the command entered by the user; FFmpeg can additionally write a full command and debug log with `-report`. [ffmpeg manual](https://ffmpeg.org/ffmpeg.html) | `stream.get_args()` yields arguments and `stream.compile()` includes the executable before `stream.run()`. [README](https://github.com/kkroening/ffmpeg-python), [API reference](https://kkroening.github.io/ffmpeg-python/) |
| Run and observe | The CLI executes the transcode; `-progress` emits periodic `key=value` records and a final `progress=end`. `-report` writes command and log to a file. [ffmpeg manual](https://ffmpeg.org/ffmpeg.html) | `run()` invokes FFmpeg and can capture stdout/stderr; `run_async()` is documented. [API reference](https://kkroening.github.io/ffmpeg-python/) |
| Record evidence | `ffprobe` JSON, `-progress`, and `-report` provide raw materials for a custom record. `-report` includes the full command line and debug log, so its contents require care when the command contains credentials. [ffprobe manual](https://ffmpeg.org/ffprobe.html), [ffmpeg manual](https://ffmpeg.org/ffmpeg.html) | The API offers probing results, compiled arguments, and captured output/error data from which a caller can build a record. [API reference](https://kkroening.github.io/ffmpeg-python/) |

**Positioning inference, narrowly stated:** The cited documentation does not describe a single bundled workflow that applies a project's own preflight policy and generates/validates a structured conversion receipt. This is an observation about the cited pages, **not** proof that FFmpeg or ffmpeg-python cannot support such a workflow; their APIs and CLI primitives can be composed to do it. FFmpeg's conversion and filter breadth, and ffmpeg-python's graph construction, are strengths to acknowledge rather than deficiencies to imply. Any PyFFmpegCore comparison should demonstrate its own workflow from this repository and avoid claims of superior speed, codec coverage, or unique command preview.
